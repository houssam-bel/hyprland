# hyprland

Modular Arch Linux dotfiles built around **Hyprland's Lua configuration**,
with a **Matugen** pipeline that repaints the entire desktop from the current
wallpaper — compositor borders, bar, launcher, notifications, terminal, GTK
apps and the lock screen, all from one command.

Design borrows heavily from Aylur's dotfiles: settings split into small
single-purpose modules, one source of truth for applications and paths, and
colour treated as generated data rather than something you hand-edit in nine
files.

```
SUPER + W          random wallpaper -> everything recolours
SUPER + SHIFT + W  pick a wallpaper through rofi
SUPER + SHIFT + T  force light/dark, ignoring the wallpaper
```

## Directory layout

The repository mirrors `~/.config` under `config/`, so `install.sh` is a flat
symlink of each component.

```
hyprland/
├── install.sh                       # symlink (or copy) config/* into ~/.config
├── packages/
│   ├── pacman.txt                   # official repositories
│   └── aur.txt                      # AUR packages
├── docs/
│   ├── keybindings.md               # every bind, in one table
│   └── theming.md                   # the Matugen pipeline in detail
└── config/
    ├── hypr/
    │   ├── hyprland.lua             # entry point — hands off to settings/init
    │   ├── hyprlock.conf            # lock screen (hyprlang, not Lua)
    │   ├── hypridle.conf            # idle timeouts (hyprlang)
    │   ├── hyprlock-colors.conf     # ← generated by Matugen
    │   ├── settings/                # configuration modules (Lua)
    │   │   ├── init.lua             # module loader: order, uncaching, errors
    │   │   ├── monitors.lua         # display topology & monitor rules
    │   │   ├── programs.lua         # default applications & script paths
    │   │   ├── autostart.lua        # daemons, background services & panels
    │   │   ├── environment.lua      # environment variables & cursors
    │   │   ├── permissions.lua      # Wayland/Hyprland security permissions
    │   │   ├── look_and_feel.lua    # gaps, borders, blur, animations
    │   │   ├── input.lua            # keyboard, mouse, touchpad, gestures
    │   │   ├── keybindings.lua      # all keyboard and mouse bindings
    │   │   ├── window_rules.lua     # window, layer & workspace rules
    │   │   └── colors.lua           # ← generated by Matugen
    │   ├── scripts/                 # executable helpers (Bash)
    │   │   ├── wallpaper.sh         # wallpaper + full retheme
    │   │   ├── theme.sh             # force light/dark
    │   │   ├── clipboard.sh         # cliphist through rofi
    │   │   ├── screenshot.sh        # grim + slurp + swappy
    │   │   ├── record.sh            # wl-screenrec / wf-recorder
    │   │   └── powermenu.sh         # rofi session menu
    │   └── assets/
    │       └── wallpapers/          # seed wallpapers
    ├── waybar/     config.jsonc · style.css · colors.css ←
    ├── rofi/       config.rasi  · theme.rasi · colors.rasi ←
    ├── swaync/     config.json  · style.css · colors.css ←
    ├── kitty/      kitty.conf   · colors.conf ←
    ├── matugen/    config.toml  · templates/
    ├── gtk-3.0/    settings.ini · gtk.css ←
    ├── gtk-4.0/    settings.ini · gtk.css ←
    └── qt6ct/      qt6ct.conf
```

`←` marks a file Matugen regenerates. They are committed with seed palettes
because several of them are hard requirements — a missing `waybar/colors.css`
stops Waybar rendering entirely, and a missing `rofi/colors.rasi` makes rofi
fail theme validation and refuse to open. See `.gitignore` for how to stop
them showing up dirty in `git status`.

## Install

Requires Arch Linux and a Hyprland build with **Lua configuration support**
(`~/.config/hypr/hyprland.lua` rather than `hyprland.conf`). Check with
`hyprctl version`; if your build reads `hyprland.conf` and ignores
`hyprland.lua`, this configuration will not load — see
[Troubleshooting](#troubleshooting).

```bash
git clone https://github.com/houssam-bel/hyprland ~/dotfiles
cd ~/dotfiles

./install.sh --dry-run      # see exactly what it would do
./install.sh --packages     # install packages, then link everything
```

`install.sh` symlinks each directory under `config/` into `~/.config`, so
editing `~/.config/hypr/settings/input.lua` edits the repository and
`git diff` stays meaningful. Anything already at a destination is **moved**
to `~/.config-backup-<timestamp>/`, never deleted. Re-running is a no-op.

| Flag | Effect |
|---|---|
| `--dry-run` | Print every action, change nothing |
| `--copy` | Copy instead of symlink, if you want the two to diverge |
| `--packages` | Also install `packages/pacman.txt` and `packages/aur.txt` |
| `hypr waybar` | Install only the named components |

Then:

```bash
~/.config/hypr/scripts/wallpaper.sh random   # generate the first palette
hyprctl reload && hyprctl configerrors       # should print nothing
```

## How the theming pipeline works

One command changes every colour on the system. The chain is deliberately
linear, with no step that guesses:

```
wallpaper.sh
   │
   ├─ awww img … --transition-type grow      set the wallpaper, animated
   ├─ echo path > ~/.cache/current_wallpaper  remember it for restore & lock
   │
   ├─ magick … -resize 1x1                    mean luminance of the image
   │     └─ >55% → light, else dark           unless ~/.cache/theme_mode pins one
   │
   └─ matugen image WALLPAPER --mode MODE
         │
         ├─ hypr/settings/colors.lua      → post_hook: hyprctl reload
         ├─ waybar/colors.css             → post_hook: pkill -SIGUSR2 waybar
         ├─ swaync/colors.css             → post_hook: swaync-client -rs
         ├─ kitty/colors.conf             → post_hook: pkill -SIGUSR1 kitty
         ├─ rofi/colors.rasi              (no hook — rofi re-reads on launch)
         ├─ gtk-3.0/gtk.css               (no hook — GTK apps read at startup)
         ├─ gtk-4.0/gtk.css
         └─ hypr/hyprlock-colors.conf     (no hook — hyprlock reads at launch)
```

Two decisions worth knowing about:

**Reloads live in Matugen, not in the script.** Each `[templates.*]` block owns
its own `post_hook`, so `matugen image X` on the command line behaves exactly
like `wallpaper.sh` — one code path instead of two that drift apart.

**Lua's `require()` cache is the trap.** It memoises by module name, so after
Matugen rewrites `colors.lua`, a `hyprctl reload` would happily serve the
*previous* palette. `settings/init.lua` clears `package.loaded` for every
module before loading, which is what makes the reload real.

`docs/theming.md` has the full detail, including how to add a new consumer.

## The Lua configuration

`hyprland.lua` contains no settings. It calls `require("settings/init").load()`,
and `settings/init.lua` owns three things:

1. **Load order**, declared once next to the reasoning. `environment` before
   `autostart` (daemons must inherit the right variables), `monitors` before
   `window_rules` (whose `monitor_w`/`monitor_h` expressions resolve against
   them), `window_rules` before `autostart` (last matching rule wins, and
   nothing should start before its config applies).
2. **Uncaching**, so a reload re-reads changed files.
3. **Error isolation**: a syntax error in one module is reported to stderr and
   as an on-screen notification, and the remaining modules still load. A
   broken `window_rules.lua` costs you window rules, not your keybindings.

`settings/programs.lua` is pure data — no `hl.*` calls, just a returned table
of applications, the main modifier and absolute script paths. Change your
terminal there and every bind, rule and autostart entry follows.

## Helper scripts

All in `config/hypr/scripts/`, all `shellcheck`-clean, all runnable by hand.
Binds point at scripts and never at inline shell pipelines: a pipeline in a
bind cannot be tested on its own and turns quoting into a minefield.

| Script | Modes |
|---|---|
| `wallpaper.sh` | `random` · `pick` · `restore` · `init` · `/path/to/img` |
| `theme.sh` | `light` · `dark` · `toggle` · `auto` · `status` |
| `clipboard.sh` | `show` · `delete` · `wipe` |
| `screenshot.sh` | `region` · `window` · `output` · `full` |
| `record.sh` | `region` · `screen` · `region-audio` · `screen-audio` · `stop` · `status` |
| `powermenu.sh` | — |

Notes on the two that carry real logic:

**`wallpaper.sh`** detects its backend (`awww`, falling back to `swww` — the
two take the same flags), waits for the daemon's socket with a real readiness
loop rather than a `sleep 1` guess, and originates `grow` transitions at the
cursor. `init` restores the cached wallpaper or picks a random one on a first
run, which is why autostart has no sleep chain in it.

**`theme.sh`** writes `~/.cache/theme_mode`. `wallpaper.sh` reads that file
before running luminance detection, which is what makes a forced mode survive
the next wallpaper change instead of being silently overridden. `theme.sh auto`
removes the pin and re-runs detection.

## Keybindings

`SUPER` throughout. Full table in [`docs/keybindings.md`](docs/keybindings.md).

| Key | Action |
|---|---|
| `Return` | Terminal |
| `` ` `` | Drop-down scratchpad terminal |
| `D` / `R` / `Tab` | App launcher / run / window switcher |
| `E` / `B` | File manager / browser |
| `Q` / `SHIFT+Q` | Close / force kill |
| `F` / `SHIFT+F` | Fullscreen / maximise |
| `Space` / `P` / `A` / `G` / `T` | Float / pseudotile / pin / group / split |
| `←↑↓→` | Focus (`SUPER+ALT+ZQSD` is the AZERTY home-row alternative) |
| `SHIFT + ←↑↓→` | Swap window |
| `Numpad 0-9`, digit row | Workspace 1-10 (`SHIFT` moves, `CTRL` sends silently) |
| `U` / `SHIFT+U` | Scratchpad toggle / send there |
| `Print`, `SHIFT/CTRL/ALT+Print` | Screenshot region / window / monitor / all |
| `V` / `SHIFT+V` | Clipboard history / delete an entry |
| `C` | Colour picker |
| `W` / `SHIFT+W` | Random / pick wallpaper |
| `SHIFT+T` / `CTRL+T` | Force light-dark / back to automatic |
| `L` / `SHIFT+P` | Lock / power menu |
| `F9`-`F11` | Record region / monitor / stop |

**Workspace switching is keycode-based, not keysym-based.** Every Numpad key
emits two different keysyms depending on NumLock, which is why most Numpad
configs found online work until NumLock is toggled once and then silently
stop. Raw `code:NN` bindings are read before XKB translation, so they behave
identically in both states — and are immune to the AZERTY layout, which is the
same reason the digit row is bound as `code:10`-`code:19`.

## Customising

| Want to change | Edit |
|---|---|
| Terminal, browser, launcher | `config/hypr/settings/programs.lua` |
| Keyboard layout (`fr` → `us`) | `config/hypr/settings/input.lua` |
| Monitors, resolutions, layout | `config/hypr/settings/monitors.lua` |
| Gaps, rounding, blur, animations | `config/hypr/settings/look_and_feel.lua` |
| Which apps float, opacity rules | `config/hypr/settings/window_rules.lua` |
| Bar modules | `config/waybar/config.jsonc` |
| Light/dark threshold | `LIGHT_THRESHOLD` in `scripts/wallpaper.sh` |
| Transition style | `TRANSITION_TYPE` in `scripts/wallpaper.sh` |
| Which apps get repainted | `config/matugen/config.toml` |

The keyboard layout defaults to French AZERTY. For QWERTY, set
`kb_layout = "us"` in `input.lua` — the ZQSD focus binds in `keybindings.lua`
are then worth changing to WASD, and everything else is layout-independent
by construction.

## Troubleshooting

**Hyprland ignores `hyprland.lua`.** Your build predates Lua configuration
support. `hyprctl version` tells you which you have. There is no shim here
that converts these modules to `hyprland.conf` — the whole structure assumes
Lua — so this needs a Hyprland upgrade.

**Config errors after a change.**
```bash
hyprctl reload && hyprctl configerrors
journalctl --user -b | grep -i hyprland | tail -30
```
A failed module also raises an on-screen notification naming the file.

**Colours did not change.** Check the templates actually rendered, and that no
unresolved keyword was left behind — a typo'd colour name leaves a literal
`{{...}}` in the output and is the classic silent failure:
```bash
grep -rn '{{' ~/.config/hypr/settings/colors.lua ~/.config/waybar/colors.css \
              ~/.config/rofi/colors.rasi ~/.config/kitty/colors.conf
```
That must print nothing. Then confirm the Lua contract holds:
```bash
lua -e 'local t = dofile(os.getenv("HOME").."/.config/hypr/settings/colors.lua")
        for _,k in ipairs{"primary","secondary","surface","on_surface","outline","error"} do
          print(k, t[k] or "*** MISSING ***")
        end'
```

**Waybar will not start.** Almost always a missing or malformed
`~/.config/waybar/colors.css` — a failed `@import` is fatal. Run `waybar` in a
terminal and read the first error line.

**Clicking a workspace in Waybar does nothing.** Known and deliberate. Against
a Lua-config Hyprland, Waybar sends old-style dispatcher strings that the Lua
dispatcher rejects, so click and scroll are disabled rather than left as dead
controls. Use `SUPER + Numpad`, the digit row, or `SUPER + scroll`.

**A privilege prompt never appears.** `hyprpolkitagent` is not running:
`systemctl --user status hyprpolkitagent`.

**Clipboard history is empty.** The two `wl-paste --watch` processes are not
running — text and images are separate MIME streams and each needs its own
watcher. Check with `pgrep -af wl-paste`.

**Screenshots capture nothing.** If you enabled `permissions.lua`, you enabled
enforcement without the allow rules. Both halves go together or neither.
